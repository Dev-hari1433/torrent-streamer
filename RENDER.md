# Lumora on Render Free

The root `render.yaml` defines separate Node web services for the Next.js frontend and the WebTorrent/FFmpeg API. Create a Blueprint from the GitHub repository. Render supplies each service's public URL to the other service; it also supplies `PORT`. The backend binds to `0.0.0.0` while local starts continue binding to loopback.

The current live services were created from this repository's public Git URL. [Render requires manual deploys for public-URL sources](https://render.com/docs/deploys), even when the service API reports `autoDeploy: yes`. After later code pushes, deploy both services from their Render dashboard pages. To enable automatic deploys, connect your GitHub deployment credential in Render and use the repository as a Git Provider source.

Both services use Render's Free plan in Singapore. The backend allows up to two torrents, one FFmpeg worker, 40 peer connections, and a 1 GiB selected-video limit. This limit applies only on Render; local playback remains unrestricted. The hosted filesystem is ephemeral, so downloaded media and saved torrent sessions disappear on sleep, restart, or redeploy. Uploaded `.torrent` metadata must then be re-added. The frontend may take roughly a minute to wake, followed by a separate backend wake-up. Peer and tracker availability, outbound bandwidth, and the available instance hours also affect playback.

This public demo permits anyone with its URL to add and remove streams, as requested. The frontend origin allowlist limits browser calls but is not authentication; direct HTTP clients can reach the API. Do not treat this deployment as a private media library. Uploaded torrent files should contain only media you have permission to share. Render Free can suspend services for unusually high service-initiated traffic, and free services have no persistent disk. A reliable, continuously available 5–13 GB player requires another hosting arrangement with persistent storage and adequate compute and bandwidth.

To verify after deploying, open the frontend URL, check that the engine connects, add a small legal torrent or magnet, and confirm the media plays. Check `/api/health` on the backend URL for DHT nodes and media process counts. `README.md` documents the local development and larger-media workflow.
